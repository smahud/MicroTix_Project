# Kontrak desain eksekusi — 2.1-build.1

Pemilik kontrak: TD, tasks dan quality menurut EXE-03–06. Dokumen ini menjelaskan cara memakai registry, bukan mengganti AUD/MAC/keputusan. Semua path di sini relatif akar paket; manifest memetakan target repo. Implementasi runner adalah output TK-002/TK-004, belum tersedia/dijalankan pada paket dokumentasi.

## 1. Nilai konfigurasi dan job

`parameter-registry_v2_1.json` menggunakan default bertipe, unit, scope, bounds dan alias. Slash pada tabel lama tidak menjadi nama key. `approved_default_only` berarti angka dasar telah disetujui tetapi tidak ada rentang override yang boleh diasumsikan. Nilai deployment/resource/target tidak diciptakan sebagai default. Tidak menggunakan null sebagai nol/off; null BRAND berarti belum boleh publikasi. Entitlement versi paket terpisah dari config platform dan hanya diubah lewat workflow approved. Tabel harga/kuota/tujuan rekening tetap dari master/PRD, bukan diduplikasi lagi di sini.

Migrasi config: parse duplicate-key-strict → reject unknown/ambiguous aliases → convert exact integer/rational units → validate type/bounds/cross-constraints/scope → produce canonical snapshot+hash. Konflik alias/canonical ditolak walau sama. Alias dalam tabel prose ambigu (misalnya session.idle tenant/platform) bukan key runtime; importer wajib memilih field konkret dari representasi lama yang berskema, tidak menebak dari string. Ratio JSON string decimal; `%` tidak diterima sebagai nilai runtime. CIDR harus canonical/valid dan overlap diperiksa terhadap target nyata. Keepalive25 hanya NAT; non-NAT omission tidak berarti nilai produk baru0. Read timeout ≤ deadline setiap kind; heartbeat < lease/2. Resource budget selalu fakta/profil berizin.

`job-kind-registry_v2_1.json` adalah daftar kind allowlist. Deadline sederhana60s tidak diwariskan oleh proses canary/backup/ACS. Untuk required_run_input, operator/run planner memilih durasi yang mencakup bounded work, window dan cleanup; nilai tercatat sebelum enqueue. Pending dependency tidak dapat memperpanjang grant. Per-kind retry memakai base positif dari profil, exponential full-jitter cap300s, attempt total≤5; hanya kegagalan terbukti sebelum efek. Formula delay untuk retry ke-n: uniform[0,min(cap,base*2**(n-1))]; random draw disimpan pada attempt untuk diagnosis, bukan secret. Default baru tidak ditentukan dengan tebakan. Fairness/CPU/pool/concurrency adalah profil terukur dari TK-1001/1005; tidak dianggap kapasitas produk.

Efek DB melalui service layer/projection writer scoped tenant; dispatcher menjadi satu-satunya pengirim device mutation. Satu kind dapat melahirkan child action dengan effect boundary terpisah. Jangan menahan transaksi DB selama I/O. Kontrak outbox, idempotency, state transition dan kompensasi mengikuti AUD-13/14, EXE-01/02. Reconciliation pada policy baru tidak memberi izin membuka layanan setelah payment.

## 2. Dependency, milestone dan build scope

`agent/task-contracts_v2_1.json` memuat 85 ID lama dan241 edge eksplisit. Objective tetap tugas §9; registry melengkapi urutan dan acceptance. Field common_ref adalah JSON Pointer ke common_controls dalam berkas yang sama, wajib di-resolve sebelum eksekusi; ini menghapus salinan aturan identik tanpa menghapus field task. Prerequisite task_id merujuk expected_outputs task tersebut. TK-508 milik R4/P9. P10 tidak disekat sampai akhir: inventory/toolchain lokal lebih awal, benchmark/DR setelah artefak relevan. Build milestone berarti kode+uji lokal yang relevan; verified berarti bukti perangkat/fungsional nyata; release_enabled berarti gate+mandat produksi. Review contract dapat berlangsung sebelum seluruh runtime prerequisite tersedia. Ketergantungan pada contract tidak mengizinkan menjalankan test tanpa runner/toolchain yang sudah dibangun.

Billing P6 mendefinisikan event/transaksi dan contract ledger dari TK-003; ledger P7 mengimplementasikan konsumsi/posting. TK-607/608/609 tidak boleh diberi final verified finansial sampai TK-701–704 mengikat event tersebut dan tes rekonsiliasi lulus. Ini menghapus cycle semu P6↔P7 tanpa menghilangkan accounting. P3 adapter lokal dapat dibuat dengan simulator/protocol contract; capability verified_lab tetap menunggu build/model/licence aktual. OLT generic interface dapat disiapkan, tetapi driver tidak boleh dipilih sampai pemilik menetapkan model/protokol yang benar-benar tersedia.

## 3. Kontrak runner dan hasil

TK-002 harus menyediakan target Make yang sudah ditentukan tugas §6. Tambahkan CLI runner test sebagai output implementasi: `python -m MicroTix_test_runner --case ID --profile PATH --evidence DIR`. Ini **spesifikasi perintah masa depan**, bukan perintah yang tersedia di ZIP ini. Registry case/action/assertion adalah input; runner tidak boleh mengubah expected berdasarkan actual. Selector menutup dependency transitif, membekukan assertion applicable dan resource set lalu memvalidasi profile. Case baseline84, supplemental acceptance172 dan ASVS requirements adalah kelas terpisah; build acceptance checklist85 bukan84 runtime cases tambahan.

Runner exit0 hanya bila semua applicable mandatory assertions PASS dan cleanup aman; exit1 bila invariant/assertion FAIL; exit2 untuk BLOCKED prerequisite; exit3 untuk invalid registry/profile/input. NOT_RUN tidak dihitung PASS. Runner emit JSON per assertion: case_id, assertion_id, expected_source, actual, result, command/steps, started/ended UTC, monotonic duration, source/artifact/config/fixture hash, scope, reviewer_type, cleanup. actual=null wajib NOT_RUN. Missing executable returns BLOCKED, bukan mock PASS. Sintaks module ini dibangun TK-002; implementasi dapat memakai pytest/Playwright di belakang interface dengan ADR kecil yang tidak mengubah hasil.

Task completion wajib mengikat seluruh requirement clause applicable, bukan hanya dua smoke assertions supplemental. Cases lama yang sudah membuktikan predicate identik dapat digunakan kembali melalui exact evidence mapping, tanpa mengulang aksi yang sama. Jumlah requirement/edge tidak dipakai sebagai pembuktian atomic-clause completeness; test author memecah source compound clause menjadi assertion terpisah sebelum test freeze. `sumber/audit/Requirements_Traceability_Matrix.json` menyimpan edge desain, tidak mengklaim verified coverage.

## 4. Fixture CSV boundary yang dapat direproduksi

Gunakan schema PRD §11 (rujukan lama §10 pada test common dikoreksi), mode create, UTF-8 tanpa BOM, LF, csv.writer dialect Excel dengan newline LF. Header: customer_code,customer_name,service_code,service_type,username,package_code,address. 10000 record, customer_code=C00000..C09999, customer_name=Synthetic, service_code=S00000..S09999, service_type=pppoe, username=u00000..u09999, package_code=FIXPKG. Tenant fixture memiliki package FIXPKG dan capacity override10001; seed bukan kuota komersial. Credential dibangkitkan internal sesuai create mode tanpa menyertakan secret fixture literal.

Buat skeleton address kosong, hitung byte aktual termasuk header+LF; target10485760. Selisih positif dibagi quotient/remainder ke address setiap record, isi karakter ASCII `A`. Ini field address yang telah terdaftar, tidak menambah kolom notes/padding. `address` impor adalah teks opsional, bukan nomor/username/URL dan tidak dieksekusi. Tidak ada numeric field length baru yang diturunkan dari padding. Batas total file menjadi bounded-input ceiling; implementasi tidak boleh menambahkan pembatas field yang tidak disetujui sehingga fixture sah ditolak tanpa decision record. Fixture generator wajib assert jumlah record10000, field count7, username≤64byte, package valid dan ukuran exact. Variant10485761 menambah satu `A`; variant10001 record memakai file kecil agar batas diuji independen. BOM/quoted comma/multiline/leading-zero/invalid-row cases dibuat terpisah. Bila schema direvisi resmi sehingga fixture tidak lagi semantik valid, regenerate melalui rule baru dan invalidasi expected fixture hash; jangan menganggap rejection semantic sebagai byte-limit proof. Byte-limit overshoot mengikuti baseline422, bukan413 yang diinventaris sendiri.

## 5. Accounting month boundary dan real protocol

Dua sub-run, hasil tidak saling menggantikan. (A) `integration_replay`: PostgreSQL nyata, handler accounting yang sama, authenticated NAS context sintetis terikat fixture; timestamp event pada2026-01-31T16:59:59Z dan2026-01-31T17:00:01Z (midnight Asia/Jakarta), arrival order Stop→Start→Interim dan duplicates. Simpan fixture packet fields/hash dan arrival/event times; no fake Acct-Stop. Scope hanya partition/dedup/usage logic. (B) `authorized_protocol_lab`: NAS/FreeRADIUS nyata dengan grant cukup untuk melewati boundary tenant kalender sebenarnya; jangan mengubah clock NAS/server. Start sebelum boundary, Interim/Stop setelahnya; delay/reorder/retransmit hanya lewat harness yang diizinkan. Jika window tak melintasi boundary, sub-runB NOT_RUN/BLOCKED; sub-runA bukan G1 proofB. Keduanya memeriksa session identity, no-double-count, stale unknown, retained live state dan cleanup. T21-ACC-01 final protocol PASS memerlukan sub-runB; A boleh selesai sebagai bukti lokal yang eksplisit.

## 6. Local profile, remote target resolver dan readiness tokens

Schema JSON Draft2020-12: execution-profile.schema.json untuk local/CI; target-registry.schema.json untuk referensi File2. Strict parser juga menolak duplicate JSON keys, nonfinite numbers dan placeholder. Run profile READY bukan factual-ready sampai semantic preflight memverifikasi file/commit/config hash, resource budget, owner grant path/scope/window, permitted operation, runner existence dan evidence sink. Build stage tidak membutuhkan artifact yang belum dibangun; test stage memerlukannya. Source workspace canonical realpath wajib di dalam grant; symlink traversal ditolak. No network probing untuk memvalidasi dokumen.

Remote resolver: seluruh target_id unik case-sensitive; root File2 gns3/application + external jump/compute registry disatukan; collision ditolak. Setiap jump_target_id menunjuk ssh_jump dalam environment/scope grant; walk graph tanpa cycle; compute_target_ids menunjuk gns3_compute yang permitted dan identity/pin lengkap. Resolver tidak memindai host untuk mencari pengganti ID. allowed_management_ips adalah IP literal valid, bukan DNS wildcard; HTTPS DNS hasil harus subset allowlist dan pin/CA valid; redirect dilarang. Schema memastikan shape, semantic checker memastikan scope, refs, IP, dates, modes, service/fault grant dan required input. Production tidak termasuk target schema lab ini. File2 DRAFT tetap bukan grant. Bahan implementasi validator target tersedia sebagai spesifikasi dan script statis, tidak mencoba koneksi.

Token V0=manifest bytes+contract match; EXECUTION_PROFILE_READY=semantic local preflight atau remote V1–V3; FIXTURE_READY=seed+fixture+baseline+hash; FAULT_GRANT_READY=operation+target+window+recovery; MODEL_CAPABILITY_READY=exact model evidence atau emulator-contract-only (tidak setara); PRIMARY_SECONDARY_ROUTES_READY=actual independent routes/failure domains; AUTHORITATIVE_FIXTURE_READY=owned fixture scope tanpa mengklaim cutover lulus. Setiap token evidence memiliki issuer/type/time/scope/hash; teks token bukan boolean true.

## 7. Applicability rilis, sumber keamanan dan keputusan

Release applicability menggunakan resource/feature catalog serta introduced_in pada assertion. Semua cross-tenant/security common controls berlaku pada SET resource yang hadir dan disetujui; selector harus menginventaris API/routes/models dan menolak resource tak terdaftar, bukan menyembunyikannya melalui exclusion. R1 tidak perlu ACS, tetapi endpoint ACS yang ternyata aktif diR1 menghasilkan scope error. Masing-masing feature flag sandbox boleh membuka fitur untuk test di lingkungan terotorisasi; flag produksi menunggu gate.

ASVS register memuat seluruh253 requirement L1+L2 dari release5.0.0. APPLICABLE dan CONDITIONAL_UNTIL_INVENTORY tidak berarti PASS. Teknologi tidak dipakai (misalnya OAuth/SAML/GraphQL/WebRTC) hanya N/A sesudah absence dibuktikan dari routes/config/dependencies dan reviewer menyetujui; jika ditemukan dipakai, seluruh section terkait aktif kembali. Clause scope generic tidak dikecualikan hanya karena chapter mengandung teknologi khusus. ASVS6.3.3 vs mandat MFA tenant tercatat SEC-DEC-01: implementasi tetap mempertahankan kebijakan sumber sampai owner memilih perubahan; G2 auth assurance menunggu disposition. Tidak melonggarkan G2 dengan N/A palsu. RADIUS legacy PAP/CHAP/MSCHAP dan protokol cryptography dinilai sebagai boundary interoperability tersendiri; jangan klaim seluruh protokol memenuhi algoritme kriptografi aplikasi modern dari hasil web ASVS.

## 8. Evidence, review dan definition of done

Baseline artifact hash/manifest, owner mandate dan current task wajib ada pada setiap checkpoint. Codex mereview perubahan Claude pada scope+diff+evidence, bukan sekadar status pesan. Maksimum3 fix rounds per task; putaran baru memerlukan temuan baru atau blocker teratasi. Dokumentasi tidak menyediakan token/provider quota/SSH/password. Prompt tidak dianggap sandbox: launcher implementasi TK-002 menegakkan workspace, command/egress/secret boundaries melalui host capabilities yang nyata. Bila alat enforcement tidak tersedia, jangan menyatakan larangan telah ditegakkan otomatis.

Contract complete → implementation local → automated tests → distinct reviewer → verified scope → release gates adalah milestone terpisah. Professional sign-off, production grant dan independent semantic audit tidak boleh direkayasa. Report terminal menyebut scope/ID yang siap dan yang terblokir, bukan satu klaim semua produksi siap.
