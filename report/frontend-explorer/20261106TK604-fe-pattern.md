## Section 1 — Routing & adding a new tenant-scoped page + nav entry

**Routing file: `apps/web/src/app/App.tsx`** (single file, declarative `Routes`).

Structure:
- Every page component is a **`lazy()` import at the top** (e.g. `const BackupsPage = lazy(() => import('../features/backups/BackupsPage'));` — App.tsx:8–28), wrapped in a global `<Suspense fallback={<PageFallback />}>` (App.tsx:84) whose fallback renders `<Skeleton>` blocks (`PageFallback`, App.tsx:30–39).
- Public routes: `/`, `/login`, `/register`, `/verify`, `/recover` (App.tsx:86–90).
- `/app` → `AppIndexRedirect` → `/app/${ctx.active_tenant_id}/overview` (App.tsx:63–68, 91).
- Tenant scope: single splat route `<Route path="/app/:tenantId/*">` wrapping `<RequireAuth>` then a nested `<Routes>` of relative paths (App.tsx:93–194).
- **`TenantRoute`** (App.tsx:49–60) is the per-page guard: reads `useParams<{ tenantId }>`, checks session, verifies membership `ctx.tenants.find((t) => t.id === tenantId)`, and **redirects foreign tenants to `/not-found`** (comment cites AC-TEN anti-enumeration). It uses a **render-prop children signature**: `<TenantRoute>{(tid) => <BackupsPage tenantId={tid} />}</TenantRoute>` — the page receives `tenantId: string` as a prop.
- Fallback inside tenant routes: `<Route path="*" element={<Navigate to="overview" replace />} />` (App.tsx:190).
- `RequireAuth` (App.tsx:42–47): shows `PageFallback` while `loading`, redirects to `/login` if `!ctx?.user`.

**Exact steps to add the billing route** (mirroring e.g. `backups`, App.tsx:146–151):
1. `const BillingPage = lazy(() => import('../features/billing/BillingPage'));` near App.tsx:21.
2. Same for `ActivationPage` (`features/activation/ActivationPage`).
3. Inside the nested `<Routes>` (after `packages`, App.tsx:184–189):
   ```tsx
   <Route path="billing" element={<TenantRoute>{(tid) => <BillingPage tenantId={tid} />}</TenantRoute>} />
   <Route path="activation" element={<TenantRoute>{(tid) => <ActivationPage tenantId={tid} />}</TenantRoute>} />
   ```

**Nav entry: `apps/web/src/design-system/components/AppShell.tsx`** — `NAV_GROUPS` const (AppShell.tsx:145–181). The billing entry **already exists**:
```ts
{ to: 'billing', labelKey: 'nav.billing', icon: 'wallet', permission: 'payments.verify', release: isReleased('billing') },
```
(AppShell.tsx:152) — `to` is a *relative* path; `SidebarNav` renders `NavLink to={`/app/${tenantId}/${e.to}`}` (AppShell.tsx:197). An `activation` entry does **not** exist yet; per UI_UX.md the activation flow is reached from billing (“Menunggu aktivasi → membuka U10”), so you may add a nav entry or deep-link (see Section 4). `NavEntry` shape: `{ to, labelKey, icon, permission?, release? }` (AppShell.tsx:137–143). Icons are checked-in paths in `Icon.tsx` (`wallet` exists at Icon.tsx:58).

Visibility filter (AppShell.tsx:189): `g.entries.filter((e) => e.release !== false && (!e.permission || can(e.permission)))` — i.e. release flag AND permission both gate the item; groups with zero visible entries are omitted.

## Section 2 — API layer conventions

Files: `apps/web/src/api/contracts.ts` (types), `client.ts` (ApiClient interface + API_MODE), `http.ts` (fetch layer), `index.tsx` (provider + react-query client), `live/adapter.ts`, `mock/adapter.ts` + `mock/fixtures.ts`.

### 2.1 Types in `contracts.ts`
- Header comment states the money/time conventions: **money = `numeric(20,2)` as JSON string, never float; event timestamps = UTC ISO 8601; business dates = `'YYYY-MM-DD'`** (contracts.ts:1–7).
- Types are grouped under `/* ---------- Domain (Uxx) ---------- */` banners (e.g. `/* ---------- Pelanggan & layanan (U04) ---------- */` contracts.ts:195). For TK-604 add a section like `/* ---------- Billing internet (U09) ---------- */` with `InvoiceState`/`PaymentState` unions etc. Existing precedent types to mirror: `BackupArtifact` (contracts.ts:300–309), `PlatformPaymentSubmission` (contracts.ts:416–426, money as `amount: string`).
- Shared primitives already exported: `CursorPage<T> { items, next_cursor }` (contracts.ts:11–14), `ApiErrorEnvelope { code, message, request_id, locale, field_errors?, retryable? }` (contracts.ts:21–28), `FieldError` (contracts.ts:16–19).
- Backend states actually implemented (read from `backend/domains/billing/models.py`): Invoice `State = draft | open | partial | paid | void` (models.py:138–143), Payment `Method = bank_transfer | ewallet | cash | collector_cash` (models.py:240–244), Payment `State = submitted | verified | rejected` (models.py:246–249). Invoice serializer exposes `state, period_index, period_start, period_end, ... first_period_policy` (views.py:94–103).

### 2.2 `client.ts` — the typed integration boundary
- `ApiClient` interface (client.ts:94–251) declares one method per endpoint group with JSDoc citing docs. Filter-shape interfaces live here too (e.g. `ServiceListFilters`, client.ts:38–47). Add e.g.:
  ```ts
  listInvoices(tenantId: string, filters: InvoiceListFilters, page: PageParams): Promise<CursorPage<InvoiceRow>>;
  listPayments(tenantId: string, filters: PaymentListFilters, page: PageParams): Promise<CursorPage<PaymentRow>>;
  verifyPayment(tenantId: string, paymentId: string, opts?: MutationOptions): Promise<PaymentRow>;
  rejectPayment(tenantId: string, paymentId: string, reason: string, opts?: MutationOptions): Promise<void>;
  ```
- `API_MODE` from `import.meta.env.VITE_API_MODE ?? 'mock'` (client.ts:253–254). **Runtime anti-mock gate**: `if (import.meta.env.PROD && API_MODE !== 'live') throw new Error(...)` (client.ts:259–261).

### 2.3 `http.ts` — request layer
- `http.get/post/patch/put` (http.ts:88–106); base path `/api/v1` (http.ts:65); `credentials: 'same-origin'` (cookie session).
- **CSRF**: `MutationOptions { idempotencyKey?, csrfToken? }` (http.ts:46–51); headers `idempotency-key` and `x-csrf-token` (http.ts:62–63).
- **Idempotency**: helper `withIdem(existing?)` in live adapter generates `crypto.randomUUID()` once per action (live/adapter.ts:60–66). `opts()` (live/adapter.ts:56–58) attaches CSRF read from cookie `mtx_csrf` (live/adapter.ts:50–54) — set by `GET /auth/session`.
- **Errors**: non-OK → `throw new ApiError(normalizeEnvelope(raw, status), status)` (http.ts:72–80); `ApiError` exposes `.code`, `.envelope`, `.fieldErrors`, `.status` (http.ts:12–27). 204/empty body → `undefined` (http.ts:82–85).
- Cursor paging: `PAGE_SIZE_DEFAULT = 50`, `PAGE_SIZE_MAX = 200`, `pageQuery(p)` (http.ts:108–117).

### 2.4 Live adapter method pattern (complete example — customers list)
```ts
async listServices(tenantId: string, _filters: ServiceListFilters, page: PageParams) {
  return http.get<CursorPage<ServiceRow>>(`/tenants/${tenantId}/services`, pageQuery(page));
}
```
(live/adapter.ts:114–116). Mutations use `withIdem(o)` (e.g. `runBackupNow`, live/adapter.ts:225–227). For TK-604 the real backend endpoints (from `backend/domains/billing/urls.py`) are:
- `GET /tenants/{t}/invoices` — filters `state`, `period_from`, `period_to`, `service_id`, cursor/limit (views.py:280–312)
- `GET /tenants/{t}/invoices/{id}` · `GET /tenants/{t}/invoices/aging?as_of=YYYY-MM-DD`
- `GET/POST /tenants/{t}/payments` — GET filters `state`, `method`, cursor; POST is `@idempotent("internet_payment_record")` (views.py:347–387)
- `POST /tenants/{t}/payments/{id}/verify` (perm `payments.verify`, idempotent) · `POST /tenants/{t}/payments/{id}/reject`
- PDF links: `GET /tenants/{t}/documents` and `GET /tenants/{t}/documents/{id}` → `application/pdf` inline (`backend/domains/documents/urls.py:1–17`). Since http.ts is JSON-only, PDF links should be plain `href`/`window.open` to the same-origin path (or an anchor `<a href={`/api/v1/tenants/${tenantId}/documents/${id}`}>`).

### 2.5 Mock adapter requirement
- `MockApiClient implements ApiClient` (mock/adapter.ts:104) — **every ApiClient method must be implemented** (TS enforces). Fixture data lives in `mock/fixtures.ts` (e.g. `SERVICES: Record<tenantId, ServiceRow[]>`, fixtures.ts:37+); deterministic dates relative to `MOCK_NOW` (fixtures.ts:23).
- Conventions inside mock: `delay(value, LATENCY_MS=160)` (adapter.ts:65–69); `fail(code, message, field_errors?)` throws Error decorated with `.code` and `.envelope` (adapter.ts:71–85); `paginate(items, page)` implements cursor via base64 offset (adapter.ts:87–93); `permissionOr403(tenantId, permission)` enforces role permissions client-side (adapter.ts:187–192) — call it first in every tenant-scoped mock method; `tenantOr404` for existence.
- Money mutations/verify flows in mock should mimic state transitions like `approvePlatformSubmission` (adapter.ts:1016–1023: guard `if (s.state !== 'submitted' ...) fail('conflict', ...)`).
- The mock also simulates jobs deterministically (`newJob`/`advanceJob`, adapter.ts:194–264) — relevant if activation dispatches jobs (`activate_service` JobKind already exists, contracts.ts:274).

### 2.6 Provider
`api/index.tsx`: `ApiProvider` creates `QueryClient` with `staleTime: 15_000, retry: false, refetchOnWindowFocus: false` (index.tsx:20–33) and provides `useApi(): ApiClient` + `useApiMode()`. Features never import adapters directly — always `const api = useApi()`.

## Section 3 — Feature module anatomy (real examples: customers, backups, admin subscriptions)

### 3.1 Folder structure
Features are **flat page-component folders** — no hooks/ or components/ subfolders, no context, no reducer:
```
src/features/customers/  CustomersPage.tsx, CustomerDetailPage.tsx, AddCustomerDialog.tsx
src/features/backups/    BackupsPage.tsx
src/features/jobs/       JobsPage.tsx, JobDetailPage.tsx
src/features/admin/      AdminSubscriptionsPage.tsx
```
State management = **TanStack Query for server state + local `useState` for the rest**. No redux/zustand/context beyond the global providers (session, i18n, branding, toast, api).

### 3.4 Mutations + confirmations
- **`ConfirmAction`** (`design-system/components/Notices.tsx:37–100`): props `open, onClose, onConfirm, title, intent, scopeLines?, confirmLabel, confirmTone?: 'primary'|'danger', loading?, requiresReauth?, children?`. - **AdminSubscriptionsPage `act()` helper** (AdminSubscriptionsPage.tsx:47–60) is the canonical mutation wrapper:
  ```ts
  const act = async (fn: () => Promise<void>, okMsg: string) => {
    setBusy(true);
    try { await fn(); toast(okMsg, 'success'); await queryClient.invalidateQueries({ queryKey: ['platform-submissions'] }); setSelected(null); }
    catch (err) { const e = err as { envelope?: { message?: string } }; toast(e.envelope?.message ?? t('common.error_generic'), 'danger'); }

  ```
  Called as `void act(() => api.approvePlatformSubmission(selected.id), t('admin.approved_toast'))` inside `onConfirm` (AdminSubscriptionsPage.tsx:196–199). - Dialog form errors: AddCustomerDialog maps `e.envelope?.field_errors` to per-field messages, else shows `e.envelope?.message` (AddCustomerDialog.tsx:100–110).
- Toast usage: `const { toast } = useToast();` → `toast(msg, 'success' | 'danger' | 'info' | 'warning')` (Toast.tsx:31–38).

## Section 5 — i18n conventions + exact steps to add keys

- Catalogs: flat JSON **key → string**, `locales/id/web.json` and `locales/en/web.json` (both 910 keys). Source of truth = `id` (I18N.md §6); `useT`'s `MessageId` is `Extract<keyof typeof idWeb, string>` so **a key missing from `id` is a compile error** (useT.ts:9).
- Provider: `I18nProvider` wraps `IntlProvider` (react-intl), locale cookie `mt_locale`, fallback chain visitor-cookie → Accept-Language → `id` (i18n/index.tsx:28–48). No pseudo-locale file exists in `locales/` — the mock `getEnums` appends `(en)` to simulate translation (mock/adapter.ts:317–319).
- Usage: `const t = useT();` → `t('billing.title')`, placeholders ICU-style `t('x', { count: 3 })` — never string concatenation (useT.ts:14–25). Dynamic enum labels: `useEnumLabel()` → key `enums.<group>.<value>`, raw value as fallback (useT.ts:41–56); role keys `role.<role>`.
- Key naming (observed): `<feature>.<thing>` (e.g. `customers.col.customer`, `backups.run_confirm_title`), `nav.*`, `common.*`, `enums.<group>.<value>`, `admin.queue_submitted`, `validation.<code>`, `permission.<slug>`, `freshness.*`, `table.*`, `bulk.*`.
- **Steps to add keys**:
  1. Add the same key to BOTH `locales/id/web.json` and `locales/en/web.json` (values with identical ICU placeholders).
  2. Dynamic keys referenced via template literals must be registered: `scripts/check_i18n.py` expands `t(\`prefix.${var}\`)` only for prefixes listed in its `ENUM_VALUES`/`DYNAMIC_KEYS` maps (check_i18n.py:25–73) — add your prefix there (e.g. a new `enums.invoice_state.` list) if you use dynamic keys, or `ID-EXTRA`/missing failures will trip.
  3. Verify: `cd apps/web && pnpm i18n:check` (or `make i18n-check`). It exits 1 on: keys missing in id **or** en, placeholder parity mismatch, unresolved templates, or **unused keys in id** (`extra_id`, check_i18n.py:107–150) — so don't leave orphan keys.
  4. Unit parity is additionally asserted by `release-flags.test.ts` (same key sets id/en, placeholder parity, no empty values).
  5. `pnpm i18n:build` regenerates catalogs from `scripts/build_catalogs.py` — NOTE: that script has its own inline `MSGS` dict (build_catalogs.py:13–19) that appears to be the historical generator; the live catalogs in `locales/` are the checked-in source of truth, edit them directly.

### Gotchas summary
- **Anti-mock production gate is double**: vite build plugin throws unless `VITE_API_MODE=live` (vite.config.ts:10–23) and client.ts throws at runtime in PROD non-live (client.ts:259–261).
- **CSRF**: every mutation must carry `x-csrf-token` from cookie `mtx_csrf` (live adapter does this via `opts()`/`withIdem()` — just route mutations through those helpers).
- **Idempotency-Key** mandatory for money/commit mutations — use `withIdem`.
- **i18n parity**: `pnpm i18n:check` fails on *extra/unused* keys too; keep catalogs exactly in sync; `useT` type-safety means `id` catalog must contain every literal key.
- **Release-flag test**: `release-flags.test.ts:45` hard-asserts billing false — update together with the flag flip.
- **R2 gating is scattered** (AppShell, CustomersPage columns, DataParts StatusQuad, CustomerDetailPage tab, OverviewPage onboarding) — grep `isReleased('billing')` before/after flipping.
- **Empty tenants in e2e**: seeded tenant has no billing data; assert honest empty states, not fabricated rows.
- Money formatting only at the view layer via `formatMoney` — never `Number()` arithmetic on contract strings for business logic.
- `quick_tab: 'paid_awaiting_activation'` already models the U09→U10 hand-off in `ServiceListFilters` + mock.
