### REV-1311-01 (P1, OPEN partial → CLOSED) — parser menghapus penjaga ejaan prefix

**Defect (dibuktikan controller):** writer baseline menyimpan kwargs URL
MENTAH ke `scope = f"{operation}:{tenant}:{resource}"`; view baseline
mengonversi kwargs dengan stdlib `uuid.UUID` yang menerima ejaan
`uuid:<hex>`, `urn:<hex>` (tanpa `uuid`), prefix berulang
`urn:uuid:uuid:<hex>` / `urn:urn:uuid:<hex>` (posisi tenant MAUPUN
resource). Parser 0004 versi lama hanya mengenali `urn:uuid:` tetap /
dua segmen polos → baris valid jatuh ke `__unparsed__` (baris mati tak
terjangkau) → klaim canonical baru melewati penjaga → retry pasca-upgrade
membuat submission + file fisik kedua (live controller: 1→2, tiga varian
FAIL; semua langkah exit 0, assertion effects==1 yang gagal exit 1).

**Perubahan (koreksi minimum R4, bukan daftar pengecualian prefix):**
`backend/domains/jobs/migrations/0004_idempotency_identity.py`
- `_split_legacy_scope` ditulis ulang **grammar-driven**: kandidat
  pemisahan = SETIAP posisi kolon pada `rest`; kandidat sah bila tenant
  DAN resource sah menurut grammar baseline — tenant: stdlib `uuid.UUID`
  (grammar persis writer lama) ATAU literal fallback `platform`
  exact-case; resource: `''`, `uuid.UUID`, atau sisa verbatim untuk
  operasi opaque (`identity_conflict_resolve`). Tanpa cabang prefix tetap
  per ejaan.

  menuntut tenant_i berakhir literal `urn`/`uuid` (non-hex) — mustahil
  valid; kolon posisi 0/`platform` serupa. Konsekuensi: >1 interpretasi =
  data asing → **`AmbiguousLegacyScope` fail-stop** (rollback atomik

  lowercase; `'PLATFORM'` garbage tidak diberi split hidup — catatan
