## 4. Keputusan engineering

- Aktivasi via PATCH access-accounts per item (endpoint ada, teruji,
  diaudit) — BUKAN job engine baru: ACT-05 "job anak per service" penuh
  (NAS verify + hold) adalah ranah TK-602/603 (G1-gated); slice ini jujur
  menampilkan kelayakan DB + label NAS terpisah (UI_UX §8).
- Kelayakan = tidak ada invoice open/partial DAN pernah ada invoice lunas
  ("sudah bayar menunggu aktivasi"); akun suspended tanpa tagihan lunas
  bukan kandidat billing (alasan ditampilkan, bukan disembunyikan).
- `quick_tab=paid_awaiting_activation` services-list tetap stub backend
  (kosong) — TIDAK dipakai UI; kelayakan dihitung dari invoice+akun nyata.
- Dokumen PDF via tautan same-origin (sesi cookie terkirim otomatis; GET
  tanpa CSRF); e2e memverifikasi byte `%PDF` + content-type nyata.
- Seed e2e memakai jalur services nyata agar dokumen/kwitansi/outbox ikut
  terbentuk; reset tidak menyentuh bukti immutable (trigger DB + FK
  PROTECT by design — percobaan delete tenant justru membuktikan
  proteksinya).
