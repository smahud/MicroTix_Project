### AUTH-R2-01 — P1 — authority is stale again after enrollment I/O

R1 REV-1711-05's exact after-preflight gap is fixed by
`backend/domains/jobs/engine.py:602–609`. However that check runs before the
whole handler. `network/handlers.py:78–80` passes **ownership only** into
`finalize_verification`. The service probes remote TLS at
`network/services.py:1202–1216`, then starts a separate transaction and checks
only `ownership_guard` at `:1259–1262`, creating Router at `:1263`, completing
enrollment at `:1277` and activating WG/SSTP credentials at `:1296–1305`.
No current actor/membership/permission recheck exists at that post-I/O domain
effect boundary. `JobContext.assert_owned` validates only lease/token/state,
not authority (`jobs/engine.py:194–217`).

Concrete flow: valid owner creates WG or SSTP enrollment → real handler reaches
TLS probe → independent connection commits membership revocation → probe
returns → still-owned job creates router and applies peer/account despite
revoked permission. This does not require an attacker, stale worker, invalid
payload or unlicensed device. Valid lease does not supply authority. Task
J20-A06 explicitly requires current authority before each sensitive commit and
zero peer/router effects after revocation.

Probe:
`authority/test_authority_r2.py::test_revocation_during_enrollment_probe_prevents_new_router`,
parametrized WG/SSTP. Actual production handler and service are unchanged;
only TLS I/O is controlled with Events. It asserts different database PIDs,
committed revocation during the probe, bounded thread completion and complete
outcome, then requires **zero new Router and credential state pending**.
Root runtime result: **FAIL for WG and SSTP**, each with router1, completed
enrollment, applied credential and job succeeded after committed revocation.
Both separate-connection and complete-worker assertions passed; these are
acceptance failures, not harness errors. Controller maps AUTH-R2-01 to residual
**REV-1711-05**, preserving the exact after-preflight fix.

Minimum correction: recheck current authority on the same short transaction
that commits post-I/O router/enrollment/credential effects, using existing
helpers and a narrow service callback if needed. Preserve separation of DB and
I/O, honest outcome for denied authority and successful valid async enrollment.
Add the barrier regression for both protocols; no architecture rewrite or
session-cookie payload is needed.

### AUTH-R2-02 — P1 — B6 chooses simulator instead of the selected adapter

`radius/handlers.py:264–271` unconditionally imports and instantiates
`RouterOsSimulator`, regardless of active adapter. Its simulated positive
readback changes DB enforcement to LOCAL and run to ROLLED_BACK (`:286–291`),
then normal verifier returns success (`:330–351`).

The production selector `adapters/routeros/factory.py:24–30` chooses
ApiSslAdapter for `MT_ROUTEROS_ADAPTER=api_ssl`. Its actual
`rollback_radius` explicitly fails closed with `cutover_pending_lab`
(`adapters/routeros/apiclient.py:328–329`). B2/B5 already use the selected
adapter; B6 bypasses both its safety gate and actual device readback. A
simulator verdict cannot prove that a registered production router rolled
back. Existing authoritatively marked run, a failed cutover run or a run
created before changing adapter configuration can enter the registered B6
handler through a rollback job payload. The existing HTTP view currently
enqueues only ordinary cutover, so this probe establishes the explicit
task0020 B6-handler acceptance path, not a currently exposed HTTP rollback
button. That limits reachability but does not supply valid device readback.

This behavior predates the correction, but is within explicit J20-A07 and R1
REV-1711-08 closure: verifier evidence must be honest and negative/unknown
device rollback cannot become succeeded/LOCAL. It does **not** require
enabling currently gated real mutations or conducting a device audit. Minimum
correction is to use the existing adapter factory and preserve fail-closed
behavior; do not activate unverified mutations.

Probe `authority/test_authority_r2.py::test_b6_uses_selected_adapter_instead_of_simulator_success`
sets selected adapter api_ssl and spies on its real rollback method while
delegating the unmodified implementation. No remote I/O can occur because that
method deliberately throws before device use. Required outcome: selected
adapter used, no success claim, enforcement remains RADIUS_AUTHORITATIVE.
Root runtime result: **FAIL**, selected adapter calls0,
succeeded/rolled_back/local with simulated positive readback. Controller maps
AUTH-R2-02 to residual **REV-1711-08**, preserving controlled negative-readback
closure.
