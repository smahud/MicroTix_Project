## Findings and closure assessment

### REV-1311-01 — partial correction; accepted baseline grammar remains broader

`backend/domains/jobs/migrations/0004_idempotency_identity.py:107–138`
recognizes a three-segment `urn:uuid:<UUID>` prefix or exactly two standard
tenant/resource segments. The baseline writer
`git show 9903d9b:backend/domains/common/idempotency.py` retains URL kwargs
verbatim in `scope = operation:tenant:resource`. Baseline Django membership
queries and `tenant_context._validate_uuid` ultimately use stdlib
`uuid.UUID`, whose accepted strings also include `uuid:<UUID>`,
`urn:<UUID>` and repeated lowercase `urn:`/`uuid:` prefixes.

Pure execution of the candidate parser and stdlib UUID on synthetic IDs:

| Tenant spelling | Baseline UUID accepts | Migrated identity matches canonical tenant/resource |
|---|---|---|
| canonical / upper / compact / braced | yes | yes |
| `urn:uuid:<UUID>` / `{urn:uuid:<UUID>}` | yes | yes |
| `uuid:<UUID>` / `urn:<UUID>` | yes | **no** |
| `urn:uuid:uuid:<UUID>` / `urn:urn:uuid:<UUID>` | yes | **no** |

For `payment_submission:uuid:<UUID>:` the parser returns `None`; lines173–186
retain it under operation `__unparsed__`. For repeated `uuid:` after URN the
parser can split a non-UUID tenant and resource incorrectly. Neither form
matches runtime lookup at `common/idempotency.py:309–320` (operation and
canonical tenant) or canonical claim at:340–342. Merely retaining the
unreachable row does **not** guard a canonical retry of the accepted old
identity. Root has been asked to reproduce actual old-source HTTP upload →
real schema migration → current HTTP retry, including ambiguous response.
This source report does not claim that reproduction was run by this agent.

Risk: an accepted old scope may lose its effective replay guard despite
retaining the physical row, allowing a new submission/file on retry. Severity
is **P1 if the root actual HTTP duplicate probe confirms this path**;
source-only assessment at this point is an open compatibility defect.

Minimum correction: recover tenant/resource boundaries by validating the
same UUID grammar used by the baseline, with a unique canonical
interpretation; use fail-stop/reconciliation when the identity genuinely
cannot be determined. Avoid adding one fixed-prefix branch per discovered
example. Keep platform remap, principal isolation, completed/ambiguous
retention, history and write-freeze requirements. Closing acceptance:
old-source accepted UUID forms on tenant/resource, known and unknown
outcomes, retry under canonical and alias spelling, one logical action/file,
no second claim/effect; unresolved scope must not silently enable execution.
